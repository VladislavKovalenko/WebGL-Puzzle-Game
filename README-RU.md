# «Филворды Василия Ивановича» — словесная головоломка на Unity Web с элементами легкого хоррора

<img width="1607" height="950" alt="image" src="https://github.com/user-attachments/assets/17c7870e-b32e-4943-ba78-8f0e56791105" />

**Платформа:** Web (Яндекс Игры)  
**Жанр:** Словесная головоломка / легкий хоррор  
**Движок:** Unity  
**Статус:** На модерации в Яндекс Играх

---

Браузерная головоломка по поиску слов, разработанная для Яндекс Игр.

Игрок проводит пальцем по соседним буквам, чтобы находить спрятанные слова на процедурно сгенерированной сетке. Каждая ошибка отнимает жизнь из общего запаса. Потеря всех жизней сбрасывает прогресс всей кампании. Прохождение уровня без ошибок возвращает одну жизнь.

Игра оборачивает эту механику в атмосферу легкого хоррора: за вашей игрой наблюдает дед, чье настроение зависит от оставшихся жизней — он спокоен, когда все идет хорошо, и приходит в бешенство, если вы ошибаетесь. Прохождение уровней открывает новые этапы в рамках 30-уровневой кампании с шаблонами сложности и опциональной механикой фонарика, ограничивающей видимость экрана.

---

## Особенности

- Процедурно сгенерированные и гарантированно решаемые поля со словами
- Кампания из 30 уровней
- Словарь на 400 слов из CSV-файла
- Звуковая система на FMOD
- Архитектура на Zenject и UniRx
- WebGL-билд для Яндекс Игр с отдельным загрузочным пайплайном
- Корректная инициализация аудио и обработка потери фокуса с учетом ограничений браузера

---

## Чем интересен этот репозиторий

Геймплей строится вокруг простой механики поиска слов, однако основная инженерная работа была сосредоточена в трех системах:

1. **Надежная инициализация аудио в Web**, где браузеры блокируют воспроизведение звука до первого взаимодействия пользователя со страницей.
2. **Процедурная генерация игровых полей**, гарантирующая полную решаемость без ручной сборки уровней.
3. **Разделение состояния сессии и постоянного прогресса**, благодаря чему неудачный забег не портит сохраненные данные.

Ниже подробно описано устройство каждой из этих систем.

---

## 1. Загрузочный пайплайн (Bootstrap Flow)

**Файлы:** `Bootstraper.cs`, `LoadManager.cs`, `LoadingScreenManager.cs`, `FMODBankLoader.cs`, `FMODFocusHandler.cs`

Браузеры блокируют воспроизведение звука до тех пор, пока пользователь не взаимодействует со страницей. Обычный WebGL-билд, пытающийся воспроизвести звук автоматически, может привести к тишине или ошибкам в консоли. В этом проекте проблема решена с помощью отдельной Bootstrap-сцены.

- `IAsyncInitService` — контракт, который реализуют все стартовые сервисы.
- `Bootstraper` собирает все зарегистрированные экземпляры `IAsyncInitService` через Zenject и ожидает их параллельную инициализацию с помощью `UniTask.WhenAll`.
- Каждая задача инициализации оборачивается в блок `try/catch`, благодаря чему сбой одного сервиса не приводит к зависанию всего процесса загрузки.
- `FMODBankLoader` загружает банки FMOD через `RuntimeManager.LoadBank` и ожидает их полной готовности.
- Как только все сервисы завершают инициализацию, `Bootstraper` напрямую вызывает `LoadManager.OnServicesReady()`. Процесс запуска не использует отдельный сигнал `AllServicesAreLoadedSignal`.
- `LoadManager` отображает подсказку «Нажмите любую кнопку» и вызывает `YG2.GameReadyAPI()`. Это сообщает Яндекс Играм о готовности игры и скрывает стандартный экран загрузки платформы.
- Затем `LoadManager` ожидает первого ввода пользователя через `InputSystem.onAnyButtonPress`.
- При первом взаимодействии со страницей `LoadManager` вызывает `mixerResume()` для разблокировки звука в FMOD, после чего продолжает загрузку и переходит в сцену Главного меню.
- `FMODFocusHandler` отслеживает события `OnApplicationFocus` и `OnApplicationPause`.
- При потере фокуса вкладкой браузера он ставит мастер-шину FMOD на паузу через `setPaused(true)` и приостанавливает микшер FMOD с помощью `mixerSuspend()`.
- При возвращении фокуса мастер-шина снимается с паузы через `setPaused(false)`, а микшер возобновляет работу с помощью `mixerResume()`.

В результате получается контролируемый процесс запуска, учитывающий ограничения браузерного аудио, особенности загрузки Яндекс Игр и переключение фокуса вкладок без использования стандартной звуковой системы Unity.

## 2. Процедурная генерация игрового поля

**Файлы:** `BoardGenerator.cs`, `WordService.cs`, `BoardData.cs`

Сетка букв для каждого уровня генерируется во время выполнения. Алгоритм разделен на три этапа.

### Этап 1 — Разбиение сетки на слоты заданной длины

Метод `GetRandomLengthPartition` разбивает общее количество ячеек (`Columns × Rows`) на случайную последовательность длин слов в пределах минимального и максимального диапазонов для данного уровня.

Любое разбиение, требующее длины слова, отсутствующей в словаре, отклоняется еще до начала генерации.

### Этап 2 — Построение путей для каждого слота

Методы `TryPartitionGrid` и `TryBuildPath` рекурсивно вырезают на сетке непересекающиеся змеевидные пути — по одному пути для каждой длины слова из полученного разбиения.

Алгоритм использует случайный порядок соседних ячеек и поиск с возвратом (backtracking). Структура путей проверяется до того, как им будут назначены конкретные слова.

### Этап 3 — Назначение слов

`WordService` хранит словарь, распарсенный из CSV-файла и сгруппированный по длине слов:

```csharp
Dictionary<int, List<string>>
```

Как только найдено корректное полное разбиение сетки, каждому пути назначается случайно выбранное слово соответствующей длины.

Если какой-либо этап завершается неудачей — например, поиск с возвратом заходит в тупик или в словаре нет доступного слова нужной длины, — вся попытка отбрасывается и запускается заново. Допускается до 50 попыток на загрузку уровня.

Благодаря этому каждое сгенерированное поле гарантированно решается и при этом остается уникальным.

## 3. Состояние сессии и мета-прогресс

**Файлы:** `GameSessionModel.cs`, `LevelsModel.cs`, `GameplayModel.cs`, `GlobalGameData.cs`

Состояние игры разделено между тремя моделями с разным временем жизни, а их зоны ответственности не пересекаются.

### `GameplayModel` — уровень сцены (scene scope)

Отслеживает происходящее исключительно в рамках текущего уровня:

- Состояние игры: `Intro → Playing → Win / Lose`
- Количество найденных слов
- Общее количество слов

Модель ничего не знает о кампании или сохранениях и пересоздается при каждой загрузке игровой сцены.

### `GameSessionModel` — уровень забега (run scope)

Синглтон Zenject, живущий на протяжении всей сессии приложения. Он отслеживает:

- `GlobalLives` — общий запас жизней на весь текущий забег
- Индекс текущего уровня
- Факт получения урона на текущем уровне, который используется для определения возможности выдать бонусную жизнь за идеальное прохождение

Модель считывает структуру кампании из `CampaignRouteSO` и формирует конфигурации уровней по запросу.

### `LevelsModel` — уровень постоянного сохранения (persistent scope)

Единственный слой, работающий с сохранениями `YG2.saves`. Он отслеживает:

- Открытые уровни
- Пройденные уровни

Данные обновляются только при явных событиях победы или поражения в `LevelEndPresenter`, а не на каждом шаге игры.

В итоге неудачный забег может израсходовать жизни и сбросить прогресс кампании, не затрагивая постоянные сохранения до тех пор, пока забег окончательно не завершится. Локальная логика сцены остается локальной, а межсессионный прогресс надежно изолирован в слое сохранений.

## Реактивный слой представления

Геймплей и меню реализованы по архитектуре Model–View–Presenter (MVP) и связываются через Zenject:

- `BoardPresenter`
- `GrandpaPresenter`
- `LevelEndPresenter`
- `IntroSlidePresenter`
- `SettingsPresenter`
- `HazardPresenter`

Изменения состояний, например `GameState`, `GrandpaState` и `GlobalLives`, представлены через `ReactiveProperty<T>` и отслеживаются с помощью `.Subscribe()` в презентерах.

Презентеры инкапсулируют логику взаимодействия, в то время как представления (Views) остаются пассивными. Представления не опрашивают состояние напрямую, а лишь реагируют на его изменения.

### Архитектура событий

В проекте сознательно используется комбинация нескольких способов взаимодействия вместо одной глобальной шины событий:

- **Zenject `SignalBus`** применяется для отдельных межсценических событий:
  - `BackToMainMenuSignal`
  - `SettingsMenuOpenSignal`
- **UniRx `ReactiveProperty`** используется для передачи игровых состояний:
  - Жизни
  - Состояние игры
  - Найденные слова
- **Прямые внедренные ссылки (Direct injection)** используются для тесно связанных пар «презентер–сервис», где дополнительный слой сигналов был бы избыточным.
- `Bootstraper` напрямую вызывает `LoadManager.OnServicesReady()` после завершения работы всех асинхронных сервисов. Этот переход не отправляется через сигнал.
- Сигнал `UserGestureSignal` объявлен в `ProjectInstaller`, но в текущей реализации не используется.

## Инструкция по запуску

- Версия Unity: `6000.5.4f1`
- Установите [Extenject](https://github.com/Mathijs-Bakker/Extenject#installation).
- Установите [UniTask](https://github.com/Cysharp/UniTask#getting-started).
- Если после сборки остаются ошибки, может потребоваться [интеграция Extenject с UniRx](https://github.com/Mathijs-Bakker/Extenject#unirx-integration).
- Откройте сцену `Bootstrap` и нажмите Play. Это точка входа в игру.
- Загрузочный пайплайн инициализирует зарегистрированные сервисы, загружает банки FMOD, отображает экран готовности и ожидает первого действия пользователя для перехода в Главное меню.
